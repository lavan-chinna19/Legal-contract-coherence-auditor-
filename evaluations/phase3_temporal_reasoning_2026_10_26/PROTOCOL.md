# Phase 3 exposed temporal-development evaluation protocol

Keep four provenance strata separate: original Phase 1 cases (unchanged labels), new controlled
synthetic cases, post-implementation synthetic challenges, and provisional interpretation cases.
Independent adjudication: zero. Nothing here is a previously unseen real-world holdout. Inputs are
hashed and preserved; general grammar fixes may follow development errors, but never case-ID logic.

The exact old date checker was executed on 17 Phase 1 temporal cases before new temporal code:
38 authored/TXT/format analyses. Its TXT chronology screen reproduced TP6/FP2/FN2/TN4.
That screen's positive label is a stated chronology predicate, not legal invalidity. T09 prepayment
and T10 notice-after-end can remain arithmetic/potential warnings without becoming confirmed
contradictions. Paired existing-case metrics compare ANY temporal candidate flag, same as Phase 1.
Do not silently relabel these original examples as adjudicated conflict labels.

New synthetic confirmed-conflict labels describe explicit singleton dates, inclusive calendar-day
offset intervals, and stated event/range order under the author's deterministic construction.
Compatible upper bounds, different actors/events/agreements/phases, unknown business calendars,
conditions/amendments, approximate/ambiguous dates and missing roles do not have a firm conflict label.
Provisional interpretation cases have null gold; no TP/FP/FN/TN or legal accuracy is assigned.
Recorded expected non-conflict categories are design expectations, not expert legal truth.

For new mechanical strata report legacy any-flag SCREEN versus the same mechanical-conflict target
as an alert proxy, and new CONFIRMED_TEMPORAL_CONFLICT separately from potential candidates.
The old checker has no calibrated confirmed category; do not pretend it is a legal oracle. Also retain
new candidate-alert frequency and all potential/review/unsupported evidence to expose alert burden.

Document-case is the metric unit. Never pool repeat/input-format observations as independent examples.
Report TP/FP/FN/TN, P=TP/(TP+FP), R=TP/(TP+FN), F1=2TP/(2TP+FP+FN), FPR=FP/(FP+TN),
null undefined denominators. In intent-to-screen counts, lack of confirmation is a negative screen;
abstention on a positive remains a miss. These TNs do NOT certify parser-supported consistency.
Also report selective metrics on explicit relational decisions, reviewed/unsupported document rates,
recognized-statement parse coverage and actual relationship-check coverage. A parsed lone fact is
not counted as relational validation. Report parser exceptions separately, never silently as TN.

New cases were created by rules stored in build_dataset.py/new_cases.json; named triggers, actors,
actions, date arithmetic and compatibility are explicit. challenge_cases.json was authored after
the initial engine and remains a separate exposed diagnostic; its initial predictions are retained.
Do not overwrite any prior scientific run after a fix. Freeze each run's source/input hash manifest
before predictions; use a NEW run ID for changed implementation.

Run legacy/new temporal rules with identical original cases and source/format provenance. New rules
reuse exact Phase 2 source structure, while old rules use original legacy clauses as historically
deployed. Separately run the real frozen neural system over all 148 Phase 2 case/mode records and
require identical clause scores/evidence/severity/intervals and unchanged structural reference/graph
outputs. Date flags may change; exclude only their rule metadata from neural comparison.

Verify source spans directly against unchanged extraction. Preserve old evidence files, model/cache
hashes, structural source and uncommitted frontend work. Test grammar, original date regressions,
all Phase 2 structure cases, native full backend, real TXT/PDF/DOCX auth/history/export and frontend
compatibility. Docker runtime is NOT VERIFIED if the host engine is unavailable; no destructive repair.
